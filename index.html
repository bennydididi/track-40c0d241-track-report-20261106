完整报告

这个产品帮助有老底片的家庭用户和胶片新手，在用手机或相机翻拍负片后，解决去色罩、校正颜色并批量裁切下载正片照片的问题。

2. 短判断卡

  • 暂缓独立站投入：有搜索和软件购买线索，但网页批量转换的付费证据、去色罩效果均未取得；先保留候选词。
  • 首页主词：negative photo converter，美国英语月搜 720。来自交接核心词与本批 SERP；另外两条入口是 convert negatives to digital、negative scanner app。
  • 用户任务：上传翻拍负片 → 去色罩、校色、批量裁切 → 下载 JPG。最小交付围绕这条流程；相对单张反色工具的批量价值尚待验证。
  • 美国主词样本仅 6 条：首页 1、内页 5，混有滤镜、App、讨论和视频；有内页占位，但不能把所有搜索都当成老底片转正需求。
  • 最大风险：negativerestore、StellarInfo 已有免费网页工具；“颜色正常”若做不好，单纯反色很难收费。
  • 数据：2026-11-06 本批 PXAny 分国家月搜与 Google SERP；出价为首页顶部出价区间。Semrush S、KD、KGR、12月趋势均未取得。

赛道深挖报告格式（关键词优先，2026-11-04）

大白话、短。不得出现本机路径。查不到写「未取得」，严禁编造。 权威流程：sop-keyword-v4.md（词 → 用户任务 → 能不能交付 → 要不要做）。

1. 第一行一句话

这个产品帮助【谁】，在【什么场景】下，解决【什么问题】。

2. 短判断卡（半屏内）

  • 候选查询 + 发现路径
  • 一句用户任务（输入→输出→条件）
  • 数据口径（工具/地区/语言/窗口；缺就写未知，不填假零）

  • 主要风险 / 待验证
  • 下一步：做 / 暂缓 / 否 + 一句理由；首页主词 + 月搜

3. 关键词作战表（主体）

sop-keyword-v4.md

赛道调研 SOP（关键词优先 · v4）

一句话主线：词 → 用户任务 → 能不能交付 → 要不要做。 目的不是堆词表，也不是写百科。

依据：哥飞顾问按 benny-brain 提炼（主看 M-DEMAND-001）+ 哥飞找词/前十判断 + Cavill 2026-11-04「围着关键词、别搞复杂」。 日常深挖用本文件 + report-format-keyword.md；旧 sop-v3 / report-format-v3 仅备查。

每天只挖 1 条。交付：短结论 + 关键词作战表 + zip + 公开网页。

0. 入口

必须先有需求发掘专员的「初筛→深挖卡」：用户任务、核心词（1–3 个）、付费证据类型。缺任一项退回。口头点题也先转专员。

钉死：谁、输入、输出、只判一个用户任务。相邻机会列表即可，不掺进主表。

第一行固定：「这个产品帮助【谁】，在【什么场景】下，解决【什么问题】。」

1. 定候选词（有界扩展）

记：原词、语言/地区、发现路径（交接卡 / 词根 / 大站非品牌词 / 下拉 / 站↔词循环等）。
从核心词补一小圈同义词与工具说法（software、maker、generator、online、app 及当地说法）。
能形成可检任务、或只剩重复 → 停。词越多≠越好。
市场：US/UK/CA/AU、DE/FR/ES/IT/NL、JP/KR，各国当地语言。
本地上门履约词记量后跳过 SERP。核心词不论月搜高低都要查 SERP。

2. 词 → 一句用户任务

写清：谁、场景、输入、希望得到什么、用来做什么。
对照「搜索者预期结果 vs 我们计划交付」。错配（搜的是买东西、你却做无关工具等）→ 直接否。

3. 先看真实 SERP，再看量/KD

对核心词 + 该国月搜够用的外围词（默认 >200）查前十：

  1. 前排是工具 / 内容 / 商品 / 导航？有没有图片/答案模块抢走点击？
  2. 首页几个、内页几个？（域名 > 子域 > 子目录 > 内页）
  3. 别人内页多 → 独立站首页更有机会（举全站打别人内页）
  4. 全是大站首页 / 关键词域名 → 慎做或换尾词，禁止硬刚红海主词
  5. 竞品输入输出与缺口；最弱占位是谁
  6. 域名年龄、DR 只作观察，不写「新手友好」；样本不足十条注明条数

陷阱（直接剔除或降权）： 季节词；谷歌直达/零点击已满足；量极大但竞争异常低得不合理。

月搜/CPC：有就写，分清正数 / 返回0 / 未返回 / 未查询。
KD、KGR、12 月趋势拿不到 → 未取得，禁止估算。
KGR（可选，有数才算）= 引号 intitle 数 ÷ 月搜；约 <0.25 是哥飞案例经验线，待项目复核，非硬门槛。
低 KD 不自动做，高 KD 不自动淘汰。

4. 能不能交付（最小范围）

从最终结果倒推最小功能。
同任务同输出 → 合页（主表达进首页/主工具页，近义进正文）；任务/输出/条件真不同才拆页。
有老站且主题对口 → 优先内页小验，再考虑独立站。
答不上「我们现在能不能交出来并维护」→ 暂缓，不硬上。

5. 要不要做（商业当假设）

付费证据：真实付款 / 订阅 / 按件价（仅定价页不算）。免费或大平台替代一句。对标最多 1–2 个。
广告/定价只能当假设，不能单独证明需求。
同行定价（必做）： 前十里的工具 + 报告点名的对标 + 1 个头部 App，逐个打开真实定价页，记：免费额度（尺寸/色数/水印/导出）、各档价格+币种、计费方式（按件/买断/月年订阅）、付费解锁内容、链接+查看日期。没公开写「未公开」，打不开写「未取得」，不估价。结论三句：已付价格带、市场偏一次付还是订阅、我们的建议价（标「建议」）。定价页本身不算付费证据。 TrustMRR 收入线索（从下一条起）： 在 TrustMRR（trustmrr.com）搜对标产品/赛道名，记公开自称的 MRR/收入区间、产品链接、查看日期；找不到写「未取得」。只作商业假设的旁证，不能单独证明需求，也替代不了定价页核对。 做/不做三问：①同口径 SERP+交付差是什么；②我们能不能交付并维护；③用什么小范围证据、期限和停止条件继续。答不上 → 补证据或暂缓。
AI 压力测试：仅交接卡点名时做；测不了写「未取得（未实测）」，不写长文。

6. 报告最少要有（短卡 + 作战表）

见 report-format-keyword.md。正文顺序：

  1. 一句话定位
  2. 短判断卡（半屏内）：候选查询+发现路径；一句用户任务；数据口径/未知；SERP 承接观察；交付差异与最小范围；主要风险；下一步：做 / 暂缓 / 否 + 理由；首页主词与月搜
  3. 关键词作战表（主体）：词｜市场｜月搜｜CPC｜SERP构成+最弱｜意图｜优先级（P0首页 / P1工具页 / P2长尾 / 不做）
  4. 先做哪 3–5 词各哪页；不做的词及原因
  5. 分数（支撑）
  6. 附录：缺口、SERP 明细、用时

禁止：十项长文、词族长文、验收节点编天数、本机路径、preview/beta、编造数字。
